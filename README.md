# Adrenaline

A portable NixOS + Home Manager configuration built around
[Hyprland](https://hyprland.org) and the
[Serpantinum](https://github.com/ilyamiro/serpantinum) desktop shell, with
declarative [Matugen](https://github.com/InioX/matugen) theming.
Everything that changes per machine lives in **`variables.nix`**.

This repository is not tied to the machine it was written on. Clone it on a
fresh NixOS install, edit `variables.nix`, replace the hardware configuration,
and rebuild.

## Layout

```
flake.nix                  thin flake-parts + import-tree bootstrap
flake/                     top-level flake-parts modules
  systems.nix              supported systems
  formatter.nix            `nix fmt`
  nixos.nix                builds nixosConfigurations.<hostname>
variables.nix              the only file you normally edit
hosts/nixos/               host-specific NixOS entry point + hardware config
modules/
  core/                    boot, locale, networking, nix, users, packages…
  hardware/                GPU, audio, Bluetooth, power, storage
  desktop/                 Hyprland, greetd, portals, Serpantinum (system)
  home/                    Home Manager modules
    hyprland/              Hyprland Lua config fragments
    nvim/                  Neovim Lua config
    serpantinum/           Matugen templates + Serpantinum settings
assets/wallpapers/         wallpapers installed to ~/Pictures/Wallpapers
```

`flake/` contains only flake-parts modules; `import-tree` imports every file
in it. NixOS and Home Manager modules stay in `modules/` and are imported by
the host and the Home Manager entry point, so adding a new file there does not
silently turn it into a flake output.

## First install

1. Install NixOS (the graphical ISO is easiest), then clone this repository:

   ```sh
   sudo git clone <your-repo-url> /etc/nixos
   cd /etc/nixos
   ```

   If you clone somewhere else, update `flakeDir` in `variables.nix` and use
   the real path in the commands below.

2. Generate the hardware configuration for **this** machine:

   ```sh
   sudo nixos-generate-config --root /
   sudo cp /etc/nixos/hardware-configuration.nix \
     /etc/nixos/hosts/nixos/hardware-configuration.nix
   ```

   The checked-in `hosts/nixos/hardware-configuration.nix` is a placeholder
   with example disk labels. Do not boot from it unchanged.

3. Edit `variables.nix`:

   - `name`, `username`, `email`, `hostname`
   - `initialPassword` (change it with `passwd` after the first login)
   - `stateVersion` if you are installing a different NixOS release
   - `timeZone`, `locale`, `keyboardLayout`
   - `bootloader`, `bootDevice`, `kernel`, `cpuVendor`, `gpu`, `nvidiaOpen`
   - `browser` (`librewolf`, `firefox`, or `both`)
   - `wallpaper` (filename stem from `assets/wallpapers/`)
   - fonts, cursor, `gaming`, `flatpak`, extra packages, SSH keys

4. Build and switch:

   ```sh
   sudo nixos-rebuild switch --flake /etc/nixos#nixos
   ```

   The flake attribute is `#<hostname>` from `variables.nix`.

After the first boot, the `rebuild` and `update` shell aliases are available
(they use `flakeDir` from `variables.nix`).

## What is included

### Desktop

- Hyprland with UWSM, launched through `tuigreet`
- Serpantinum shell (bar, launcher, lock screen, notifications, wallpaper
  picker) auto-started as a user service
- XDG desktop portals, PipeWire, NetworkManager, Bluetooth, power profiles
- A custom Hyprland Lua configuration in `modules/home/hyprland/`
- Neovim with a Matugen-driven colour scheme, managed file-by-file

### Applications

`modules/home/packages.nix` installs:

- VS Codium (`pkgs.vscodium`)
- Obsidian (`pkgs.obsidian`)
- Anki (`pkgs.anki`)
- Prism Launcher (`pkgs.prismlauncher`)
- Bitwarden (`pkgs.bitwarden-desktop` — `pkgs.bitwarden` is a throwing alias
  in current nixpkgs)
- Zathura

LibreWolf and/or Firefox are configured through `programs.librewolf` /
`programs.firefox`. Set `browser` in `variables.nix`.

### Terminal

The kitty configuration is a Home-Manager adaptation of the original config,
with `window_padding_width` set to **15**. It keeps:

- JetBrainsMono Nerd Font at size 9
- hidden window decorations and no close confirmation
- `Ctrl+Insert` / `Shift+Insert` copy & paste
- CSI-u mappings for `Shift+Enter` and `Alt+Shift+Enter`
- block cursor, no blink, no audio bell
- powerline tab bar
- a `colors.conf` include generated by Matugen

Zsh comes with autosuggestions, syntax highlighting, fzf, zoxide, direnv and
Starship.

## Theming

When the wallpaper changes, Serpantinum runs Matugen and regenerates:

| File | Used by |
| --- | --- |
| `~/.config/hypr/colors.lua` | Hyprland borders/shadow/background |
| `~/.config/kitty/colors.conf` | kitty (upstream Serpantinum template) |
| `~/.config/gtk-3.0/gtk.css` | GTK 3 apps |
| `~/.config/gtk-4.0/gtk.css` | libadwaita / GTK 4 apps |
| `~/.config/btop/themes/matugen.theme` | btop |
| `~/.config/nvim/lua/matugen.lua` | Neovim |
| `~/.cache/wal/colors.json` | Pywalfox |

**Do not manage those files with Home Manager.** The Home Manager modules in
this repository deliberately leave them alone. In particular, GTK is
configured with `gtk.theme = null` so Home Manager never writes `gtk.css`.

The repository's own Matugen templates are appended to Serpantinum's config in
`modules/home/serpantinum/default.nix`.

### Pywalfox (browser theming)

The native host manifest is installed automatically for the browser you
selected, and the Matugen hook calls `pywalfox update` only when the extension
is connected. To enable live browser theming:

1. Install the **Pywalfox** extension from addons.mozilla.org
   (`pywalfox@frewacom.org`).
2. Rebuild. The manifest is written to:
   - LibreWolf: `~/.librewolf/native-messaging-hosts/pywalfox.json`
   - Firefox: `~/.mozilla/native-messaging-hosts/pywalfox.json`
3. Change the wallpaper once (or run `matugen image ...`); the browser colours
   update with the rest of the desktop.

The add-on itself cannot be installed declaratively; install it once per
browser profile.

## Customising

### Wallpapers

Drop images into `assets/wallpapers/`, set `variables.wallpaper` to the
filename **without** its extension, and rebuild. All images in that directory
are installed to `~/Pictures/Wallpapers/`; Serpantinum's wallpaper picker and
Matugen both use that folder.

The checked-in `black-hole.png` is the default.

`variables.wallpaper` is applied by a per-login user service, so a wallpaper
picked at runtime lasts until you log out. To make a choice permanent, point
`variables.wallpaper` at it and rebuild.

### Packages

- System-wide: add names to `variables.extraPackages` (dotted attribute paths
  such as `"nerd-fonts.iosevka"` work).
- User profile: add names to `variables.extraHomePackages`.
- Structured changes: add a module under `modules/core`, `modules/desktop`, or
  `modules/home` and import it from the matching `default.nix`.

### Settings

Serpantinum's declarative settings live in
`modules/home/serpantinum/default.nix`. The module regenerates
`~/.config/serpantinum/settings.json` on every activation so changes are not
lost after the shell has been started once.

Useful Serpantinum keybinds (with `SUPER` as the modifier):

| Key | Action |
| --- | --- |
| `SUPER + D` | Launcher |
| `SUPER + W` | Wallpaper picker |
| `SUPER + C` | Clipboard |
| `SUPER + N` | Network |
| `SUPER + V` | Volume |
| `SUPER + B` | System panel |
| `SUPER + L` | Lock |
| `SUPER + R` | Reload shell |

## Maintenance

```sh
# Update all flake inputs
sudo nix flake update --flake /etc/nixos

# Rebuild
sudo nixos-rebuild switch --flake /etc/nixos#nixos

# Format the Nix files
nix fmt
```

Garbage collection runs weekly and deletes generations older than 14 days
(`variables.gc`).

## Notes and limitations

- The placeholder `hardware-configuration.nix` **must** be replaced; its UUIDs
  and device names will not match your machine.
- Nothing in this repository has been built on the machine it was written on.
  The first `nixos-rebuild` may reveal nixpkgs option renames; fix them in the
  obvious module.
- `variables.initialPassword` is only used when the account is first created.
  Change it immediately with `passwd`.
- Nvidia users must set `gpu = "nvidia"` and, for pre-Turing cards,
  `nvidiaOpen = false`.
- Secure Boot, disk encryption, and secrets management are intentionally out
  of scope. Add them before using this on a machine with sensitive data.
